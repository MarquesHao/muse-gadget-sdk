# Muse 小工具 · 需求清单 V1（2026-11-13 用户定版）

硬件：微雪 ESP32-S3-Touch-AMOLED-1.75C 带电池版（SKU 33691），预计 2026-11-16（周一）到货。
底座：Meta 官方 Muse Gadgets SDK（facebookincubator/muse-gadget-sdk），账号侧验证已于 2026-11-13 全部通过（SDK token 已建并存入保险库、App 开发者模式已开）。

## 总目标（用户原话口径）
通过这个小玩意实现大部分 Muse 功能，不用掏手机。路线：先做聊天挂件，跑稳后再介入家里设备。

## 需求 1：三种模式（定版，共三种，不要多不要少）
- 模式一「全语音对话」：像打电话一样实时语音对话，回复出声。
- 模式二「语音发送、文字回」：按键说话，回复只显示文字，不出声（开会、安静场合用）。
- 模式三「纯会议模式」：见需求 5，全程静音录音，出纪要＋原始录音。
- 三种模式要在设备上方便切换（交互开发时定：菜单选模式为底线）。
- **音量可调**：凡是有语音输出的模式，必须能调节声音大小（官方设置里已有音量项，保留并确保模式内好找）。

## 需求 2：唤醒
- 第一版先用按键通话（按键开始通话，或按键说话、文字回复）。
- 目标形态「无感唤醒」：日常聊天中随口说一句「对吧，Muse」即可唤醒，并且能把唤醒**之前**的一段对话内容带入，形成连续对话。
- 已知难点（开发评估）：① 自定义中文唤醒短语要单独训/配唤醒模型，ESP32-S3 算力可跑但准确率要调；② 「带前文」需要设备端滚动录音缓冲（PSRAM 8MB 可存数分钟音频），常开监听费电；③ 常开录音涉及旁人隐私，默认只在用户开启的场合用。此项排二期，先做按键版。

## 需求 3：待机电子宠物 ＋ 全系统状态窗
- 待机画面用电子宠物（不用时钟，用户已有 Apple Watch）。
- 宠物不只是装饰：用它的状态/表情反馈「Muse 整体是否在工作、哪些旁聊（AI 员工）在忙」，做成一个全方位的氛围监控窗。
- 状态映射草案（待用户确认）：睡觉＝全部空闲；忙碌动作＝有员工在干活；开心＝任务完成；竖耳朵/变色报警＝有异常要处理（如设备掉线报警）。
- 实现前提：宠物动画本体是固件资源替换（一期可做）；状态联动需要 Muse 侧把系统状态喂给设备，属定制开发，排二期。
- 动作库扩充（2026-11-13 用户要求丰富设定，先列草案）：待机眨眼、伸懒腰、打哈欠、跑步赶工、敲键盘、开心跳跃、竖耳朵警觉、趴下安静（会议/录音中）、低电量蔫了、充电回血、摇尾巴打招呼（开机/唤醒时）。
- **宠物形象定版（2026-11-13）：就用 Muse 自己的形象（Jolly）**，用户喜欢。好处：官方固件自带该形象资源（esp32/avatar/ 的 jollybot.gif 与 happy_anim），我们做的是在它身上扩动作。注意：该形象不在 Apache 开源授权范围内，个人自用没问题，不拿去商用或公开发布素材。

## 需求 4：家居控制（后期）
- 聊天挂件跑稳后，再接入家里设备（走设备自带的局域网隧道能力，后续对接 Home Assistant 方向）。
- 目标：大部分日常功能经小工具完成，不掏手机。

## 需求 5：会议模式（2026-11-13 用户明确立项）
- 会议模式：开启后全程监听并保存录音，设备全程静音不出声。
- 交付物两件，缺一不可：① 会议纪要（结论、决定、待办、负责人）；② **原始录音文件**，方便用户自己回听、复核、再总结。
- 屏幕在录音期间要有明确的「录音中」状态显示（宠物趴下安静＋录音标记，见需求 3）。
- 排期：二期（依赖静音链路与录音上传/转写链路）；V1 先把文字（静音）模式做稳。

## 二期需求（2026-11-13 定版）：无感交互
- 目标：不按键、不喊固定唤醒句。设备待机常听，靠「关键词守门＋语义复核」判断要不要应答。
- 守门词：muse、缪斯。出现在话里任何位置即触发；不使用「你好」类开头（用户明确不要）。
- 触发动作：Jolly 竖起耳朵，进入聆听姿态；把触发前后的一整句录下（环形缓冲保留词前几秒）。
- 复核：整句送云端，由 Muse 判断是不是在叫它。是→进入正常对话交互；不是→不发声、不显示，静默退回待机。
- 未触发时：不录音上传、不处理，纯待机。
- 待验项（二期探针）：守门识别（乐鑫 MultiNet 自加指令词）的准头与常开功耗；云端判断后「静默退下」在 SDK 通道里的实现方式。
- 排期：周一硬件测试跑通后启动，竖耳朵动画为二期第一件。
